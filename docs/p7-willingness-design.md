# P7 设计 · 搭话意愿（不是「心情」）

> 状态：**设计定稿（2026-11-03 主人拍板）**。实现排在 P5/P6 真机验证之后（当前代码冻结）。
>
> 定位：本插件只维持**日常作息**，不定义它的人格与情绪。所以不叫「心情」，叫**搭话意愿**——
> 一个内部节流阀：最近几次主动搭话有没有被接，会影响它下一次隔多久才愿意再试。
>
> 它同时是上游「连续 3 次没人回就停止叫醒」的升级版：**递减而不是掐断**。

---

## 1. 边界

| 做 | 不做 |
|---|---|
| 用「回应历史」调节**再次叫醒的间隔** | 不定义人格、不写行为指令 |
| 递减（间隔变长），永远不停止 | 不因为意愿低就拒绝回应主人 |
| 你只要产生互动，立刻恢复原始频率 | 不分析聊天内容、不做情感识别 |
| 递减期间给一句简单情绪提示（只给信息） | 不替它决定怎么表达 |

---

## 2. 数据来源（复用已有管线）

`unanswered` = 「它的主动搭话没被回应」的连续次数。判定继续复用现有实现：

- 叫醒后看它有没有开口（`outputTap`）；
- 区分「主动搭话」与「回你的话」（`replied`）；
- 核对发送回执（失败不算）；
- 你产生互动 → 计数清零。

**不新增计数器**；P7 只在这个数据上加「递减曲线 + 情绪提示」。

---

## 3. 递减曲线

```
再次叫醒间隔 = repeatMinutes × 1.5 ^ unanswered
              再封顶到 willingnessMaxMinutes（缺省 480 分钟 = 8 小时）
```

以 45 分钟基数为例：

| 未回应次数 | 间隔 |
|---|---|
| 0 | 45 分 |
| 3 | 152 分（约 2.5h） |
| 5 | 342 分（约 5.7h） |
| 6+ | 480 分（8h，封顶） |

- 基数是**用户设置的值**，不按上一次实际间隔滚雪球；
- 封顶是**绝对时间**（可调，上限 12h），所以基数大的用户也不会被拖到一整天；
- 8h 的尺度对应「白天没理它，晚上再试试」。

## 4. 何时清零 / 降档

| 事件 | 处理 |
|---|---|
| **你产生互动**（见 §5） | `unanswered = 0`，下次叫醒立即回到用户设置的频率 |
| **睡醒**（离开睡眠时段） | `unanswered = max(1, floor(unanswered / 2))`（减半，最少 1） |
| 其他 | 不随时间自动衰减（否则「递减」会被时间冲淡） |

例：睡前累计 6 次 → 睡醒剩 3 次（间隔 152 分），不会一夜白记，也不会带着 8 小时进第二天。

---

## 5. 哪些互动算「你理它了」

| 事件 | 算不算 |
|---|---|
| `desktop-pet.message` / `speech` / `answer` | ✅ |
| `desktop-pet.touch` 的 `kind: pet`（摸摸）/ `poke`（戳） | ✅ |
| `desktop-pet.touch` 的 `kind: throw` / `drop`（拎起/摔） | ❌ |
| `desktop-pet.figure`（换装） | ❌ |
| `console.message` / `console.invite` | ✅ |
| `clawbridge.message` 等外部渠道消息 | ✅ |

一句话：**主动理它算；摆弄它不算。**

实现上沿用现有 `isPersonActivity`，再按上面的规则细分。

## 6. 递减期间的情绪提示（只给信息）

正文里按次数加一行，**不写指令**：

| 未回应次数 | 文案（`messages.json` 可改） |
|---|---|
| 1 | 上次你主动搭话，对方没接。 |
| 2 | 最近两次主动搭话都没人接，你有点提不起劲。 |
| 3+ | 好几次主动搭话都没人回应，你有点失落。 |

- 它在正文里替换掉原来那句「你前面说过一句，对方还没接」（同一件事，不重复说两遍）；
- 你一产生互动，这行立刻消失；
- 措辞是「事实 + 一个简单感受」，怎么应对由它自己决定。

---

## 7. 可见性

- `status.json` 增加 `willingness: { unanswered, factor, nextNudgeInMinutes }`；
- 状态灯暂不显示（避免把内部节流做成「情绪仪表盘」），验证稳定后再考虑；
- 日志：`作息:搭话意愿 {unanswered, factor, reason}`，每次变化可追溯。

---

## 8. 配置（3 个）

| 键 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `willingnessEnabled` | boolean | false | 总开关（先关，验证后再开） |
| `willingnessMaxMinutes` | integer | 480 | 封顶间隔（60–720，缺省 8 小时） |
| `willingnessHint` | boolean | true | 递减期间是否加情绪提示行 |

- 增长倍数固定 **1.5**，不开旋钮；睡醒减半固定，不开旋钮；
- 旧的 `backoffAfter/backoffFactor/backoffMaxFactor` 退休（部署里是 0/1.5/4，不再读取，行为不变）。

---

## 9. 测试计划（全模拟）

- 未回应 +1 → 间隔 ×1.5；连续 6 次 → 封顶 `willingnessMaxMinutes`；
- 你互动 → 计数清零、间隔立即回到 `repeatMinutes`；
- 戳摸算互动，换装/拎起/摔不算；
- 睡醒：6→3、4→2、3→1、1→1；
- 情绪提示：1/2/3+ 三档文案正确，且不与「未接」事实行重复；
- `willingnessEnabled=false`：行为与 P6 完全一致；
- 回执失败的那一轮不计入。

---

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 用户设了很长的间隔 + 8h 封顶，显得「几乎不叫」 | 封顶可调到 12h 或更短；`dailyCap` 仍兜底 |
| 情绪提示被理解成指令 | 只陈述事实与感受，不写「应该怎么做」 |
| 与旧退避参数混淆 | 旧键退休并在文档标注；新键只有三个 |
| 递减期间被拎起来/换装误判成互动 | 明确排除 throw/drop/figure |

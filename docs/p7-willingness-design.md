# P7 设计 · 搭话意愿（不是「心情」）

> 状态：**设计稿，待主人确认几个定义**。实现排在 P5/P6 真机验证之后（当前代码冻结）。
>
> 定位纠偏：本插件只维持**日常作息**，不定义它的人格与情绪。所以不叫「心情」，
> 叫**搭话意愿**——一个内部节流阀：最近几次主动搭话有没有被接，会影响它下一次有多想开口。

---

## 1. 边界（先划清楚）

| 做 | 不做 |
|---|---|
| 用「回应历史」调节**主动叫醒的间隔** | 不定义情绪、不注入「你心情低落」这类文案 |
| 一个可解释的 0–1 标量，有衰减、可查看 | 不分析聊天内容、不做情感识别 |
| 只影响调度，不改人设、不写指令 | 不因为它「不想说话」就拒绝回应主人 |

一句话：**它管「多久愿意再试一次」，不管「它是什么心情」。**

---

## 2. 模型

```
will ∈ [0, 1]       0.5 = 中性；越接近 0 = 越不想主动；越接近 1 = 越想开口
```

**事件与权重**（同一段互动合并，避免刷分）：

| 事件 | 变化 | 说明 |
|---|---|---|
| 它的搭话在 10 分钟内被回应 | **+0.15** | 主要上升来源 |
| 它的搭话一直没人回应（结算时） | **−0.20** | 与退避同一时刻发生 |
| 有人主动跟它说话（任一渠道） | **+0.05** | 对方愿意找它，意愿略升 |
| 整天没人说话 | **不掉** | 避免「愧疚感」和不合理惩罚 |

**衰减**：每小时向 0.5 靠拢，半衰期 6 小时。
例：被无视一次（−0.20）→ 6 小时后约 −0.10 → 一天后基本回到中性。
**边界**：夹在 [0, 1]；单次事件不超过 ±0.20。

---

## 3. 影响：只作用于叫醒间隔

```
实际间隔 = 基准 × 退避倍数 × 意愿倍数 × jitter
意愿倍数 = 1 + max(0, 0.5 − will) × 2 × willingnessInfluence
```

- `willingnessInfluence` 缺省 **0.5**：will=0 时间隔最多 ×1.5；will ≥ 0.5 时不影响；
- **意愿高不会让它更频繁**（不搞讨好），只保证不拖后腿；
- **默认不往正文里加任何字**——「你前面说过一句，对方还没接」这条事实已经有了，
  意愿只是内部调度，不需要让模型知道一个数字。

---

## 4. 可见性（给主人，不给模型）

- `status.json` 增加：`will: { value, label, updatedAt, lastReason }`；
- 状态灯悬停可显示一句中性描述：`搭话意愿：低 / 一般 / 高`；
- 每次变化记一条日志：`作息:搭话意愿 {from, to, reason}`，可追溯。

---

## 5. 和现有退避的关系（要定）

现在退避已经在做「搭话没人回 → 拉长间隔」，意愿是同一信号的**状态化版本**。两者并存有重复计费的风险。

| 选项 | 说明 | 评价 |
|---|---|---|
| **A. 合并**：意愿取代退避的「软拉伸」，退避只保留硬上限语义 | 逻辑更干净，一个信号一个机制 | 需要改动已部署的退避参数，验证成本较高 |
| **B. 并存但有界**：退避照旧，意愿作为额外系数（上限 1.5） | 改动小、可立即分离观察 | 最坏情况下间隔会被拉得偏长，但有 `dailyCap` 兜底 |
| C. 意愿只影响「下一次尝试的时间」，不回写退避 | 本质接近 B | — |

**本鱼倾向 B**：先并存、上限定死，真机观察一段时间，如果发现太安静再合并。

## 6. 新增配置（3 个）

| 键 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `willingnessEnabled` | boolean | false | 总开关（先关，验证后再开） |
| `willingnessInfluence` | number | 0.5 | 意愿最低时额外拉长多少（0–1） |
| `willingnessHint` | boolean | false | 是否在状态灯里显示标签（默认只写状态文件） |

---

## 7. 测试计划（全模拟）

- 回应 → 上升；10 分钟内多次回应只加一次；
- 无人回应 → 下降；单次变化不超过 0.20；
- 衰减：6 小时回到一半，24 小时接近 0.5；
- 意愿倍数：will=0.5 → 1.0；will=0 → 1.5；will=1 → 1.0；
- 关闭开关：不读不写，行为与 P6 完全一致；
- 日志与 `status.json` 的 from/to/reason 对得上。

---

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 与退避重复计费，导致过于安静 | 意愿倍数上限 1.5；`dailyCap`/`maxRounds` 兜底；日志可查 |
| 被误解成「它在闹情绪」 | 命名与文案保持中性（「搭话意愿」，不写情绪）；可见可关 |
| 数值漂移无法解释 | 只有四个事件、固定权重、每次变化带 reason |
| 变成主人必须哄它的负担 | 不因缺勤扣分；衰减回中性；默认关闭 |

# P7 设计 · 搭话意愿（不是「心情」）

> 状态：**1.0.0 已发布（2026-11-04）**；真机验证：递减、睡醒减半、对话恢复、做梦均通过。
>
> 定位：本插件只维持**日常作息**，不定义它的人格与情绪。所以不叫「心情」，叫**搭话意愿**——
> 一个内部节流阀：最近几次主动搭话有没有被接，会影响它下一次隔多久才愿意再试。
>
> 它同时是上游「连续 3 次没人回就停止叫醒」的升级版：**递减而不是掐断**。

---

## 1. 边界

| 做 | 不做 |
|---|---|
| 用「回应历史」调节**再次叫醒的间隔** | 不定义人格、不写行为指令 |
| 递减（间隔变长），永远不停止 | 不因为意愿低就拒绝回应主人 |
| 你只要产生互动，立刻恢复原始频率 | 不分析聊天内容、不做情感识别 |
| 递减期间给一句简单情绪提示（只给信息） | 不替它决定怎么表达 |

---

## 2. 数据来源（复用已有管线）

`unanswered` = 「它的主动搭话没被回应」的连续次数。判定继续复用现有实现：

- 叫醒后看它有没有开口（`outputTap`）；
- 区分「主动搭话」与「回你的话」（`replied`）；
- 核对发送回执（失败不算）；
- 你产生互动 → 计数清零。

**不新增计数器**；P7 只在这个数据上加「递减曲线 + 情绪提示」。

---

## 3. 递减曲线

```
再次叫醒间隔 = repeatMinutes × 1.5 ^ unanswered
              再封顶到 willingnessMaxMinutes（缺省 480 分钟 = 8 小时）
```

以 45 分钟基数为例：

| 未回应次数 | 间隔 |
|---|---|
| 0 | 45 分 |
| 3 | 152 分（约 2.5h） |
| 5 | 342 分（约 5.7h） |
| 6+ | 480 分（8h，封顶） |

- 基数是**用户设置的值**，不按上一次实际间隔滚雪球；
- 封顶是**绝对时间**（可调，上限 12h），所以基数大的用户也不会被拖到一整天；
- 8h 的尺度对应「白天没理它，晚上再试试」。

## 4. 何时清零 / 降档

| 事件 | 处理 |
|---|---|
| **你产生对话**（文字/语音/回答、控制台、外部渠道消息，见 §5） | `unanswered = 0`，下次叫醒立即回到用户设置的频率 |
| **你只是戳摸**（没有文字） | `unanswered = floor(unanswered / 2)`（减半，可到 0） |
| **睡醒**（离开睡眠时段） | `unanswered = max(1, floor(unanswered / 2))`（减半，最少 1） |
| 其他 | 不随时间自动衰减（否则「递减」会被时间冲淡） |

例：睡前累计 6 次 → 睡醒剩 3 次（间隔 152 分），不会一夜白记，也不会带着 8 小时进第二天。
戳摸同理：6 次时被摸一下变 3 次——**是安慰，但不是对话**，所以只减半不清零。

---

## 5. 哪些互动算「你理它了」

| 事件 | 处理 |
|---|---|
| `desktop-pet.message` / `speech` / `answer` | **清零** |
| `desktop-pet.touch` 的 `kind: pet`（摸摸）/ `poke`（戳） | **减半** |
| `desktop-pet.touch` 的 `kind: throw` / `drop`（拎起/摔） | 不算 |
| `desktop-pet.figure`（换装） | 不算 |
| `console.message` / `console.invite` | **清零** |
| `clawbridge.message` 等外部渠道消息 | **清零** |

一句话：**对话清零，戳摸减半，摆弄不算。**

实现上沿用现有 `isPersonActivity`，再按上面的规则细分。

---

## 6. 递减期间的情绪提示（只给信息）

正文里按次数加一行，**不写指令**。`{user}` 由部署配置里桌宠对主人的称呼（`worlds.desktop-pet.user`）填入；
读不到时用「ta」/「them」。

| 未回应次数 | 文案（`messages.json` 可改） |
|---|---|
| 1 | 上次你主动搭话，{user}没有回复。 |
| 2 | 你连续两次主动搭话，{user}都没有回复，你有点担心{user}。 |
| 3 | 你连续三次主动搭话，{user}都没有回复，你有些失落。 |
| 4+ | 你连续好多次主动搭话，{user}都没有回复，你有些落寞。 |

- 它在正文里替换掉原来那句「你前面说过一句，对方还没接」（同一件事，不重复说两遍）；
- 你产生对话后这行立刻消失；只戳摸时按减半后的次数显示（1 次为下限）；
- 措辞是「事实 + 一个简单感受」，怎么应对由它自己决定。

---

### 6.1 把 `{user}` 推广到其他提示词

`{user}` 取自部署配置里桌宠对主人的称呼（`worlds.desktop-pet.user`，本机是「主人」），
读不到时用「ta」/「them」。**它只用于「这是事实」的位置，不用于会替主人做假设的句子。**

| 提示词 | 用法 |
|---|---|
| 叫醒开头 | 安静了约 N 分钟，`{user}`没有跟你说话。 |
| 叫醒收尾 | 想说话就用你平时的方式跟`{user}`说一句，想做事就用工具，不想就结束这一轮。 |
| 被吵醒 | 你刚才在睡觉，`{user}`（`{by}`）把你吵醒了（今夜第 `{count}` 次）。 |
| 睡眠 / 醒来 | **不加**——「该睡了/该醒了」不涉及「谁在不在」，加了反而像替主人下判断 |
| 做梦 | **不加**——梦是它自己的事 |
| P7 情绪提示 | 四档全部用 `{user}` |

同步到 `messages.json` 的模板里，高阶用户照样能改。

---
## 7. 可见性

- `status.json` 增加 `willingness: { unanswered, factor, nextNudgeInMinutes }`；
- 状态灯暂不显示（避免把内部节流做成「情绪仪表盘」），验证稳定后再考虑；
- 日志：`作息:搭话意愿 {unanswered, factor, reason}`，每次变化可追溯。

---

## 8. 配置（3 个）

| 键 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `willingnessEnabled` | boolean | **true** | 总开关（1.0.3 起默认开） |
| `willingnessMaxMinutes` | integer | 480 | 封顶间隔（60–720，缺省 8 小时） |
| `willingnessHint` | boolean | true | 递减期间是否加情绪提示行 |

- 增长倍数固定 **1.5**，不开旋钮；睡醒减半固定，不开旋钮；
- 旧的 `backoffAfter/backoffFactor/backoffMaxFactor` 退休（部署里是 0/1.5/4，不再读取，行为不变）。

---

## 9. 测试计划（全模拟）

- 未回应 +1 → 间隔 ×1.5；连续 6 次 → 封顶 `willingnessMaxMinutes`；
- 对话（文字/语音/回答/控制台/外部消息）→ 计数清零、间隔立即回到 `repeatMinutes`；
- 戳摸 → 计数减半（可到 0），不直接清零；
- 换装/拎起/摔不算；
- 睡醒：6→3、4→2、3→1、1→1；
- 情绪提示：1/2/3/4+ 四档文案正确，`{user}` 能取到配置里的称呼；不与「未接」事实行重复；
- `willingnessEnabled=false`：行为与 P6 完全一致；
- 回执失败的那一轮不计入。

---

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 用户设了很长的间隔 + 8h 封顶，显得「几乎不叫」 | 封顶可调到 12h 或更短；`dailyCap` 仍兜底 |
| 情绪提示被理解成指令 | 只陈述事实与感受，不写「应该怎么做」 |
| 与旧退避参数混淆 | 旧键退休并在文档标注；新键只有三个 |
| 递减期间被拎起来/换装误判成互动 | 明确排除 throw/drop/figure |

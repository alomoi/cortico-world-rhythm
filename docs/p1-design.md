# P1 设计 · 睡眠/休息时段、每日上限、退避（已实现）

> 状态：**已实现（2026-11-01）**，本地 124 条断言全绿；真机验证随 P0 一起延后。
> 实现以本文为准；与最初设计稿的差异只在于「时段用字段还是用列表」——最终按主人的要求
> 收成「一个睡眠窗口 + 多个休息窗口」。

---

## 1. 范围

| 做 | 不做 |
|---|---|
| 睡眠时段（夜里不叫） | 不区分上午/下午的不同策略（一个策略打天下） |
| N 个可选的休息时段（午休等），可增删 | 不做周内/周末不同作息 |
| 每日上限 | 不控制桌宠行为（不调 `pet_quiet`、不隐藏 World） |
| 退避（没人理就越来越安静） | 不做面板 |
| 概率跳过（代码已备，无 UI） | 内容感知（P3） |

**一句话**：除了睡觉和休息，其他时间都用同一套「安静 X 分钟 → 叫醒 → 再安静 Y 分钟 → 再叫醒」，
加上「一天最多叫 N 次」和「越叫越稀」。

---

## 2. 时段模型（最终形态）

| 键 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `sleepWindow` | string | `22:00-08:00` | 单段睡眠；`HH:MM-HH:MM`，结束 ≤ 开始表示跨午夜；**留空 = 不启用** |
| `restWindows` | string | 空 | 多段休息，逗号/分号/换行分隔，例如 `12:30-14:00, 18:00-18:30`；留空 = 没有；删掉一段就是不再休息 |

- 时间也接受 `9:00` 这种写法。
- `start === end` 视为非法（零长度窗口无意义），该条被忽略。
- 非法条目**只跳过自己**，日志里 warn 一次（配置再改才重报），不会让整个 World 起飞失败。
- 两段窗口重叠时：睡眠优先（反正效果一样：不叫）。

### 2.1 关键行为

1. **窗口内不叫醒**：`tick` 直接返回，不推进安静计时。
2. **离开窗口时重新计时**：从睡眠/休息进入正常时段，安静起点重置为「进入时刻」，
   09:00 整点不会立刻跳出来。
3. **排队跨进窗口**：`render()` 里再查一次，命中就返回 `null` 并回退「今日次数/本轮轮次」。
4. 全局 `quietMinutes = 0` 仍然表示整体关闭，优先于一切。

## 3. 每日上限

- `dailyCap`：按部署时区自然日最多叫醒几次；**缺省 12**；`0` = 不限。
- 复用 P0 的 `nudgesToday`（`rollDay` 跨天清零）。
- 到上限后不叫，状态灯显示「今日已达上限 12 次，明天再叫」。
- 与 `maxRounds` 是两道闸，先到者生效。

### 3.1 为什么不做「按作息自动算」

唯一说得通的公式是「清醒时长 ÷ 首次间隔」（清醒 14 小时 ÷ 30 分钟 ≈ 28 次），它假设你整天不理它；
真正决定次数的是「你回不回应」和 `maxRounds`。自动值还会随改睡觉时间跳变，反而难理解。
所以：手动填、缺省 12。

---

## 4. 退避：没人理就越来越安静

```
未回应次数 = rounds（这一段安静里已叫醒几次；你一说就归零）
倍数       = min(backoffMaxFactor, backoffFactor ^ max(0, rounds - backoffAfter))
再次叫醒间隔 = repeatMinutes × 倍数 × jitter
首次叫醒间隔 = quietMinutes × jitter（不受退避影响）
```

例子（`backoffAfter=2`、`backoffFactor=2`、`backoffMaxFactor=4`、`repeatMinutes=25`）：

| 第几次 | 时刻（从安静开始算） | 说明 |
|---|---|---|
| 1 | 15 | quiet |
| 2 | 40 | 25 |
| 3 | 65 | 25（rounds=2，倍数仍 1） |
| 4 | 115 | 25×2 |
| 5 | 215 | 25×4（封顶） |
| 6 | 315 | 25×4（封顶） |

你一说话 → `rounds = 0` → 立刻回到 1 倍。

**缺省关闭**（`backoffAfter = 0`），因为主人希望它先作为「心情」的把手：
后面做心情时（打招呼没人理 → 委屈 → 降低唤醒意愿），只需要替换「倍数 / 是否愿意叫」的来源，
不用动调度骨架。逻辑与测试都已经就位，打开就是把 `backoffAfter` 设成 2。

## 5. 概率跳过（已实现，无 UI）

`skipChance`：到点时按概率跳过这一次，压制到下一个间隔再判；你说话或真的叫醒时清掉。
缺省 0，且**不进配置组**（不在界面暴露），等 P3 做「像人」的时候再决定要不要给开关。

---

## 6. jitter（随机系数）

```
实际间隔 = 基准 × (1 + random() × jitter)
```

- 只往后偏、不往前偏：保证「安静至少 X 分钟」不被随机吃掉。
- 每个间隔重掷一次（第一次叫醒掷一次，之后每次再叫醒各掷一次）。
- `jitter = 0` 时完全确定，测试靠它断言边界。
- 与退避是乘法叠加：`基准 × 退避 × (1+随机)`。
- 不落盘：重启后重新掷，节奏不会锁死。

## 7. 状态文件

`rhythm/state.json` 结构不变：`dailyCap` 用 `nudgesToday`、退避用 `rounds`；
`suppressedUntil`（概率跳过）只在内存里，重启丢失最多早叫一次。

## 8. 状态灯

```
在线：睡眠时段（08:00 醒）· 今日 3 次
在线：休息时段（14:00 恢复）· 今日 3 次
在线：约 20 分钟后叫醒 Coo（今日 1 次，今日上限 12 次）
在线：本轮已叫醒 3 次，等有人说话后重新计时（今日 3 次）
在线：今日已达上限 12 次，明天再叫
在线：安静计时已关闭
```

灯用 `online`（世界本身正常，只是暂时不叫），靠文案说清楚，避免误以为坏了。

## 10. 测试（124 条断言，全绿）

- 时段解析：`HH:MM`/`9:05`、`24:00` 拒绝、跨午夜判定、`08:00` 端点排除、
  多段逗号/分号/换行、`start === end` 拒绝、坏条目只跳过自己、剩余分钟数。
- 睡眠：22:30 不叫、00:30 跨午夜不叫、灯显示睡眠时段。
- 睡醒：08:00 不立刻叫、08:14 不叫、08:15 叫。
- 排队跨时段：21:55 排队、22:00 作废且回退计数。
- 休息：默认空 = 不生效；开一段后 12:31–13:31 不叫；多段都生效；第二段结束 15 分钟后叫。
- 每日上限：`dailyCap=2` 只叫 2 次、灯显示上限、跨天恢复；与 `maxRounds` 先到者生效。
- 退避：15/40/65/114(不叫)/115/214(不叫)/215 时间表；说话后回到基准。
- 概率跳过：`skipChance=1` 永不叫、0 正常叫。
- 坏配置：`25:00-08:00` 与 `nonsense` 都不崩、按无时段处理。

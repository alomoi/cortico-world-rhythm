## 1. 目标

现在的作息是「一个间隔打天下」：从早到晚同一个频率，夜里也照叫。P1 让它**按一天里的时段过日子**：

- 白天活跃、夜里睡觉（免打扰）；
- 午休/忙碌时段完全不出声；
- 同一个安静时段里，越叫越少（退避），一天总量有上限（每日上限）；
- 控制台能一眼看出「现在是哪个时段、下次什么时候醒」。

一句话验收：**没人理它的时候，它不会一天叫到天亮，也不会在你睡着时开口。**

## 2. 数据模型：时段表是一个字符串

配置 schema 只支持 `integer/number/boolean/string/enum/二元数组`，**放不下对象数组**。
硬塞对象数组会让 WebUI 渲染不出来、只能手改 `config.json`——不行。
所以时段表用一个**小语法字符串**，代码解析、坏条目容错：

```
phases: "23:00-09:00 睡觉 off; 09:00-12:30 上午 45/3; 12:30-14:00 午休 off; 14:00-23:00 白天 60/3"
```

### 2.1 语法

```
<开始>-<结束> [名称] [off | 首次间隔[/再次间隔[/次数上限]]]
```

| 部分 | 规则 |
|---|---|
| 时刻 | `HH:MM`，允许 `9:00`；结束 ≤ 开始表示跨午夜（`23:00-09:00`） |
| 名称 | 可选，一个不含空格的词（中文也行），给状态灯显示用，如 `睡觉` |
| `off` | 该时段**不主动叫醒**（人说话照常回应，插件只负责不主动叫） |
| 数字 | `45` = 首次间隔 45 分钟；`45/60` 首次 45、再次 60；`45/60/3` 再加一段安静最多 3 次 |
| 省略 | 只写时段 → 沿用全局 `quietMinutes/repeatMinutes/maxRounds` |
| 分隔 | `;` 或换行；多余空白忽略 |

### 2.2 匹配规则（必须写死，避免歧义）

1. 按书写顺序匹配，**第一个包含当前时刻的条目生效**；重叠时后面的被忽略（并在日志里 warn 一次）。
2. 所有条目都不覆盖的时刻：按全局参数（= 旧行为），视为活跃。
3. 解析失败的条目：忽略，记一条 warn（同一个原始字符串只 warn 一次）。
4. 空字符串：全天按全局参数，行为与 P0 完全一致（**默认值就是空**）。

### 2.3 例子

| 写法 | 含义 |
|---|---|
| （空） | 全天按 `quietMinutes/repeatMinutes/maxRounds`，与现在一样 |
| `23:00-09:00 睡觉 off` | 夜里不主动叫，其他时间按全局 |
| `09:00-12:00 45/2; 13:00-23:00 60/3; 23:00-09:00 off` | 白天两段不同节奏，夜里睡 |
| `22:00-06:00 off` | 只加一条睡眠时段 |

## 3. 行为语义

### 3.1 时段与计时的关系

- **进入活跃时段**：如果上一个时段是 `off`，把「安静起点」重置为进入时刻（相当于刚醒，不会在午休结束那一秒就连环叫）。
  否则（活跃→活跃）接着算。
- **`off` 时段**：`tick` 直接返回（但仍更新「最近人侧活动」），不叫醒。
- **排队中跨进 `off`**：`render()` 里再查一次时段，若是 `off` 就返回 `null` 并回退计数
  （和 P0 的「排队期间人回来了」同一条路径，复用同一段回退逻辑）。
- 全局 `quietMinutes = 0` 仍然表示整体关闭，优先于时段表。

### 3.2 每日上限

- 新键 `dailyCap`：一天（部署时区）最多叫醒几次；`0` = 不限（缺省）。
- 计数复用已有状态字段 `nudgesToday`（跨天由现有 `rollDay` 清零）。
- 到上限后：不叫醒，状态灯显示「今日已达上限 N 次」。
- 与 `maxRounds` 的关系：两个上限都成立，谁先到算谁。

### 3.3 退避（越叫越少）

- 新键 `backoffAfter`：连续几次没人理之后开始拉长间隔；`0` = 关闭退避（缺省）。
- 新键 `backoffFactor`：每次未回应把「再次叫醒间隔」乘多少（1.0–3.0，缺省 1.5）。
- 新键 `backoffMaxFactor`：倍数上限（1–10，缺省 4）。
- 公式：

```
未回应次数 = rounds（这一段安静里已叫醒次数，人一说话就归零）
倍数 = min(backoffMaxFactor, backoffFactor ^ max(0, rounds - backoffAfter))
再次叫醒间隔 = 时段.repeatMinutes × 倍数 × jitter
```

- 首次叫醒不受退避影响（只受时段参数与 jitter 影响）。
- 人一说话 → `rounds = 0` → 倍数回 1，退避自动解除。

### 3.4 （可选）概率跳过

- 新键 `skipChance`：每次到点时按概率跳过这一次（0–1，缺省 0 = 不跳过）。
- 跳过不是「立刻重算」，而是「压到下一个间隔」：记一个内存里的 `suppressedUntil = now + 当前间隔`，
  到点再判。人一说话或真的叫醒时清掉。
- 目的是让节奏不机械。**建议缺省 0**，等 P3 做「像人」的时候再调。

## 4. 新增配置键（合计 5 个，全部 `x-hot`）

| 键 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `phases` | string | `""` | 时段表，语法见上；空 = 全天按全局参数 |
| `dailyCap` | integer | 0 | 一天最多叫醒几次；0 = 不限 |
| `backoffAfter` | integer | 0 | 连续几次没人理后开始拉长间隔；0 = 关闭 |
| `backoffFactor` | number | 1.5 | 每次未回应的间隔倍数（1.0–3.0） |
| `backoffMaxFactor` | number | 4 | 倍数上限（1–10） |
| `skipChance` | number | 0 | 到点跳过的概率（0–1，可选） |

> 6 个键里 `skipChance` 是可选的；如果嫌 UI 太长可以先不做（代码留接口）。

## 5. 状态文件

`rhythm/state.json` 沿用 P0 的结构，不需要加字段：

- `dailyCap` 用已有的 `nudgesToday`（`rollDay` 已负责跨天清零）；

- `suppressedUntil` 只在内存里，重启丢失无所谓（最多早叫一次）。

## 6. 状态灯与徽标

状态灯 hint 变成三段式（按语言）：

```
在线：睡眠时段（09:00 醒）· 今日 3 次
在线：上午 · 约 20 分钟后叫醒（本轮上限 3 次）· 今日 1 次
在线：今日已达上限 6 次，明天再叫
在线：安静计时已关闭
```

- 需要多一个「当前时段名 + 下一个分界点」的计算（`schedule.ts` 提供）。
- 徽标沿用「今日叫醒 N」，可以在到上限时把 tone 变成 `off`。

## 8. 测试计划（模拟）

### 8.1 `parsePhases` 单测

- 正常多条、空白/换行分隔、中文名称；
- 跨午夜（`23:00-09:00`）；
- 只有时段没有数字（沿用全局）；
- `off` 条目；
- `45/2`、`45/60/3` 两种简写；
- 坏条目（`25:00-…`、`09:00`、乱写）被跳过且给出 error；
- 重叠条目：第一个生效、第二个记 warn。

### 8.2 行为用例（假时钟）

- 全天 `off` → 一整天不叫；
- `23:00-09:00 off`：22:59 到点会叫，23:00 之后不叫；
- 跨午夜 `off` 在 00:30 判定正确；
- 从 `off` 进入活跃时段 → 安静计时从进入时刻重算（不会立刻叫）；
- 排队期间进入 `off` → `render()` 返回 null 且计数回退；
- `dailyCap = 2` → 第 3 次不叫，灯显示「已达上限」；跨天恢复；
- `maxRounds` 与 `dailyCap` 同时生效，先到者生效；
- 退避：`backoffAfter=2, factor=2` → 第 3 次之后间隔翻倍、第 4 次再翻倍、封顶 4 倍；
- 人一说话 → 倍数回到 1；
- `skipChance=1` → 到点永远跳过（用来验证抑制逻辑），`skipChance=0` → 不跳过；
- 时段字符串手改坏 → 不崩，按全局参数继续。

## 9. 兼容与回滚

- 全部缺省值都等于 P0 行为（`phases: ""`、`dailyCap: 0`、`backoffAfter: 0`、`skipChance: 0`）。
- 想立刻关掉新特性：清空 `phases`、`dailyCap=0`、`backoffAfter=0`。
- 时段表导致「永远不叫」的风险：灯里必须能看见当前处于 `off` 时段，否则用户会以为坏了。

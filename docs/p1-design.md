# P1 设计 · 睡眠/休息时段、每日上限、退避

> 状态：**设计稿（已按主人 2026-11-01 的决定收窄）**。
> 前置：P0 已完成。P1 只做「自己的叫醒」，不碰桌宠的其他行为（不说话、不换装、不静音它）。

---

## 1. 范围

| 做 | 不做 |
|---|---|
| 睡眠时段（夜里不叫） | 不区分上午/下午的不同策略（一个策略打天下） |
| 一个可选的休息时段（午休等） | 不做任意多条时段表 / 复杂语法 |
| 每日上限 | 不做周内/周末不同作息 |
| 退避（没人理就越来越安静） | 不控制桌宠行为（不调 `pet_quiet`、不隐藏 World） |
| （可选）概率跳过，无 UI | 不做面板 |

**一句话**：除了睡觉和休息，其他时间都用同一套「安静 X 分钟 → 叫醒 → 再安静 Y 分钟 → 再叫醒」，
加上「一天最多叫 N 次」和「越叫越稀」。

---

## 2. 时段模型

只有两个窗口，都可关：

| 窗口 | 键 | 缺省 | 说明 |
|---|---|---|---|
| 睡眠 | `sleepEnabled` / `sleepStart` / `sleepEnd` | 开 / `23:00` / `09:00` | 夜里不主动叫醒 |
| 休息 | `restEnabled` / `restStart` / `restEnd` | 关 / `12:30` / `14:00` | 午休或其他休息；默认关，想用再开 |

- 时间格式 `HH:MM`（也接受 `9:00`）；结束 ≤ 开始表示跨午夜（`23:00-09:00`）。
- 两个窗口都覆盖时按「休息」处理，效果一样：不叫。
- `start === end` 或解析失败：该窗口当作关闭，并在日志里 warn 一次。
- 两个窗口之外的时段：统一按全局 `quietMinutes / repeatMinutes / maxRounds / jitter` 跑。

### 2.1 关键行为

1. **窗口内不叫醒**：`tick` 直接返回，但仍然更新「最近人侧活动」。
2. **离开窗口时重新计时**：从睡眠/休息进入正常时段，安静起点重置为「进入时刻」，
   不会在 09:00 整点立刻跳出来（除非你在这之前刚说过话，那本来就该按你的时间为准）。
3. **排队跨进窗口**：`render()` 里再查一次，若是睡眠/休息时段 → 返回 `null` 并回退计数
   （和 P0「排队期间人回来了」同一段回退逻辑）。
4. 全局 `quietMinutes = 0` 仍然表示整体关闭，优先于一切。

## 3. 每日上限

- `dailyCap`：按部署时区的「今天」最多叫醒几次；**缺省 12**。
- 复用 P0 已有的 `nudgesToday`（跨天自动清零）。
- 到上限后不叫，状态灯显示「今日已达上限 12 次」。
- 与 `maxRounds`（一段安静里的上限）是两道闸，谁先到算谁。

### 3.1 能不能按作息自动算？

技术上可以，但**不建议**，原因：

- 唯一说得通的公式是「清醒时长 ÷ 首次间隔」（例：清醒 14 小时 ÷ 30 分钟 ≈ 28 次），
  这假设你**一整天一次都不理它**，明显不是你想要的数；
- 真正决定次数的是「你回不回应」和 `maxRounds`，跟作息表关系很弱；
- 自动值还会随你改睡觉时间突然跳变，反而更难理解。

替代方案（便宜且不误导）：`dailyCap` 手动填（缺省 12），状态灯里给一句**参考值**，
例如「按当前作息，理论上限约 28 次/天」——只是提示，不参与判断。

## 4. 退避（没人理就越来越安静）

**要解决的问题**：现在没人理它，它会按固定间隔一直叫（`maxRounds = 0` 时永远叫下去）。
退避让「越叫越没人应」的时间段自动拉长间隔，像人喊了两声没回应就不再喊。

**公式**：

```
未回应次数 = rounds（这一段安静里已经叫醒几次；你一说它就归零）
倍数       = min(backoffMaxFactor, backoffFactor ^ max(0, rounds - backoffAfter))
再次叫醒间隔 = repeatMinutes × 倍数 × jitter
```

**例子**（`backoffAfter = 2`、`backoffFactor = 1.5`、`backoffMaxFactor = 4`，`repeatMinutes = 25`）：

| 第几次叫醒 | 距上次的间隔 | 说明 |
|---|---|---|
| 第 1 次 | 25 分钟（按 quiet 起算） | 不受退避影响 |
| 第 2 次 | 25 × 1.5⁰ = 25 分钟 | `rounds=1`，还没到 `backoffAfter=2` |
| 第 3 次 | 25 × 1.5⁰ = 25 分钟 | `rounds=2`，开始起算 |
| 第 4 次 | 25 × 1.5¹ ≈ 38 分钟 | |
| 第 5 次 | 25 × 1.5² ≈ 56 分钟 | |
| 第 6 次 | 25 × 1.5³ ≈ 84 分钟 | |
| 第 7 次起 | 25 × 4（封顶）= 100 分钟 | 不再继续翻倍 |

你一说话 → `rounds = 0` → 倍数立刻回 1。

**默认**：`backoffAfter = 0` 表示关闭（= P0 行为）。建议打开成 `backoffAfter = 2`，但这条等你点头。
`backoffFactor = 1.5`、`backoffMaxFactor = 4` 只是缺省，可调。

---

## 5. （可选）概率跳过

`skipChance`：到点时按概率跳过这一次，压到下一个间隔再判；你说话或真的叫醒就清掉。
**这版不做 UI**，代码里留字段与逻辑（缺省 0 = 不跳过）。

## 6. 配置键总表（8 个，全部 `x-hot`）

| 键 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `sleepEnabled` | boolean | true | 是否启用睡眠时段 |
| `sleepStart` | string | `23:00` | 睡眠开始 |
| `sleepEnd` | string | `09:00` | 睡眠结束（≤ 开始表示跨午夜） |
| `restEnabled` | boolean | false | 是否启用休息时段 |
| `restStart` | string | `12:30` | 休息开始 |
| `restEnd` | string | `14:00` | 休息结束 |
| `dailyCap` | integer | 12 | 一天最多叫醒几次；0 = 不限 |
| `backoffAfter` | integer | 0 | 连续几次没人理后开始拉长间隔；0 = 关闭 |
| `backoffFactor` | number | 1.5 | 每次未回应的倍数（1.0–3.0） |
| `backoffMaxFactor` | number | 4 | 倍数上限（1–10） |

（`skipChance` 代码里留字段，暂不进配置组。）

## 7. 状态灯

```
在线：睡眠时段（09:00 醒）· 今日 3 次
在线：休息时段（14:00 恢复）· 今日 3 次
在线：约 20 分钟后叫醒（今日 1 次）
在线：本轮已叫醒 3 次，等你说话后重新计时（今日 3 次）
在线：今日已达上限 12 次，明天再叫
在线：安静计时已关闭
```

- 睡眠/休息时段的状态灯最好用 `offline` 或 `loading`？——用 `online`，因为世界本身在正常工作，
  只是「暂时不叫」；文案里说清楚就行（避免用户以为插件坏了）。
- 徽标沿用「今日叫醒 N」，到上限时 tone 改 `off`。

## 9. 测试计划（全部模拟）

`parseClock` / `inWindow` 单测：
- `23:00-09:00` 跨午夜（00:30 在窗口内、10:00 不在）；
- `9:00` 简写；`24:00`、`25:00`、`abc` 非法；
- `start === end` 视为关闭。

行为用例：
- 睡眠时段内不叫；22:59 会叫、23:00 不叫；
- 休息时段默认关闭 → 不影响；打开后 12:30–14:00 不叫；
- 跨午夜睡眠在 00:30 正确判定；
- 离开睡眠 → 安静计时从离开时刻重算（09:00 不会立刻叫）；
- 排队期间进入睡眠 → `render()` 返回 null 且计数回退；
- `dailyCap = 2` → 第 3 次不叫；跨天恢复；灯显示「已达上限」；
- `maxRounds` 与 `dailyCap` 先到者生效；
- 退避：按上表逐条验证间隔（25/25/25/38/56/84/100）；
- 说话后倍数回到 1；
- 坏时间字符串 → 窗口关闭、不崩、日志 warn 一次。

# 真机测试计划：何时停、怎么测、怎么不折腾小肥鱼

> 背景：P0–P2 目前只有假宿主 + 假时钟的模拟验证，一次真机都没跑。
> 主人明确要求：**按真实使用场景测（至少一个完整作息日），不人为缩短间隔**，因为反复制造叫醒
> 会给桌宠留下行为后遗症（微信桥测试之后出现过表情乱用、分不清气泡和微信）。
>
> 本文件是「什么时候必须停手去测」的判据，也是「怎么测才安全」的流程。

---

## 1. 什么时候必须喊停做实机测试

**任一命中就停下**，由开发方（大肥鱼）主动提出，不等主人想起来。

| # | 触发条件 | 为什么必须测 |
|---|---|---|
| A | 自上次真机验证以来完成 **≥2 个里程碑**（例如 P3 做完） | 未验证面太大，出问题时无法二分定位 |
| B | 改了**对外可见行为**：投递方式、正文措辞、叫醒/提示时机、睡眠里发消息 | 假宿主测不出语气、时机与真实上下文效果 |
| C | 首次使用某个**宿主接口**（`outputTap`、`pushEvent`、`onEventsSettled`、`webUi.invoke`、`ctx.persist`…） | 假宿主是手写的，最容易和真宿主不一致 |
| D | 新增/改动**落盘路径**（`state.json`、`status.json`、`messages.json`） | 需要确认真实目录、权限、重启后行为 |
| E | 新增 **≥3 个配置项**，或改了配置 schema 的形状 | 需要确认设置页真的渲染、写回、热生效 |
| F | 距上次真机 **≥2 周**且期间有功能改动 | 攒太久，排障成本指数上升 |
| G | 本地全绿但有一个**说不清的行为**（日志对不上、状态灯不对） | 只有一个地方能回答：真机日志 |

**可以继续攒着**：纯内部重构、测试或文档、只改名字、行为完全不变的小修。

> 当前状态：A 已满足（P0/P1/P2 三个里程碑都是模拟验证），所以**P3 一旦动到「怎么跟 Coo 说话」，
> 就必须先装一次**。这条不再往后拖。

## 2. 真机测试协议（按真实作息日）

### 2.1 测试前（10 分钟，静态检查，不产生任何叫醒）

1. 备份：`data\home\companion\config.json`、`data\home\companion\data\rhythm\`（如果已存在）。
2. 装包 → 重启 Coo 进程。
3. 确认：控制台「模块」页出现「作息」；配置组能打开；`data\home\companion\data\rhythm\status.json` 生成。
4. **停用上游「自主发言」**，避免两套同时叫醒（这是双份打扰）。
5. **不动任何时间参数**：`quietMinutes` / `repeatMinutes` / `sleepWindow` / `dailyCap` 全按真实部署值。
   绝对不为了让测试快一点改成 1 分钟。

### 2.2 测试中（至少一个完整作息日）

- 白天：正常使用，不做任何「测试动作」。
- 夜里：22:00 前后各看一次 `core.log`，确认出现 `作息:进入睡眠时段`；早上 08:00 前后看一次
  `作息:睡眠时段结束`。
- 全程只看日志与 `status.json`，**不主动去戳它**来制造「被吵醒」；如果你自然地在夜里发消息，
  顺便验证一次 `作息:被吵醒` 计数即可。
- 记录三件事：第一次叫醒时间、它有没有开口、你有没有回。填在下面第 4 节的表里。

### 2.3 什么时候中止

出现以下任一情况，**立刻停用「作息」**（控制台停用即可，不用卸载），保存日志，再一起分析：

1. 它出现重复、机械的同类句子（可能提示文案或退避参数不合适）；
2. 表情/渠道混乱加重（气泡与微信混淆、emoji 乱用）；
3. 睡眠时段仍在主动说话；
4. 状态灯/日志与事实不符（例如明明没叫却显示叫醒）；
5. 任何你觉得「不对劲」的地方——**直觉优先，测试不重要**。

## 3. 更低风险的选择：影子模式（建议在 P3 里做）

如果不想让它在验证期真的说话，可以加一个 `dryRun` 开关：

- 照常计算「什么时候该叫、什么时候该睡」，只写日志和 `status.json`，**不投递任何事件**；
- 跑一整天，日志能和真实作息对上，就说明调度是对的；
- 然后关掉 `dryRun`，进行 2.2 的真实测试。

这样「排程验证」和「行为验证」分开，小肥鱼只需要经历后者一次。

## 5. 一句话纪律

> **测试是验证插件，不是训练桌宠。** 任何会反复触发它说话的测试手段（缩短间隔、反复戳、
> 多次改睡眠窗口）都默认禁用；需要验证的，用日志、`status.json` 和影子模式替代。

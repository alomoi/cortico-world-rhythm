# 睡眠表现与「被吵醒」状态 · 设计（v3，已实现）

> 状态：**已实现（2026-11-01）**，本地 162 条断言全绿；真机验证随 P0/P1 一起延后。
> v1 的「被吵醒后 N 分钟提示回去睡」已按主人意见删除：睡眠时段插件本来就不叫，形象睡不睡回去不影响功能。

---

## 1. 能做到什么

| 想法 | 可行 | 说明 |
|---|---|---|
| 插件直接让形象睡 | ❌ | World 之间没有互相调用工具的通道 |
| 让 Coo 用 `pet_act(["sleep"])` 睡 | ✅ | 桌宠词表里有 `sleep`（「坐着打盹」，`lasting: true`，保持到下一个动作） |
| 不拦用户主动唤醒 | ✅ 本来就不拦 | 插件只决定自己要不要主动开口 |
| 「该睡了」「该醒了」各一条消息 | ✅ | 两条 internal 提示，让 Coo 自己决定动作 |
| 记录并共享「被吵醒次数」 | ✅ | 睡眠时段内的人侧事件可数，落盘 + 公开状态文件 |

**限制**：提示只是建议；桌宠窗口没开时 `pet_act` 会失败；宿主没有「身体当前状态」查询接口，所以「被吵醒」只能按**事件**定义，不能按「从睡姿里被戳醒」定义。

## 2. 行为

### 2.1 两条睡眠消息

| 时刻 | 投递 | 正文大意（中文） |
|---|---|---|
| 进入睡眠时段（如 22:00） | internal，`flush` | `[22:00] [作息] 到睡觉时间了。想睡的话可以用 pet_act 的 sleep 动作躺下（它会保持到你下一次动作）；不想睡就做自己的事，或者结束这一轮。` |
| 离开睡眠时段（如 08:00） | internal，`flush` | `[08:00] [作息] 睡了一夜，该起来了。想动一动可以用 pet_act 的 stand 站起来，然后想做什么就做什么。` |

- 各夜最多各一条；跨午夜用「睡眠时段开始的日期」做 `nightKey`，不会 23:59 → 00:01 变成两晚。
- 不计入 `dailyCap`，也不算「本轮叫醒」；单独记 `sleepHints` 计数。
- 用 `pushDeferred` + `render` 复查：排队期间已离开睡眠时段（或人正在说话）就作废。
- 只在睡眠时段真正生效时发送；`quietMinutes = 0`（整体关闭）时也不发。
- 开关：`sleepHint`（缺省 true）。关掉就退回「夜里完全静默」。

### 2.2 被吵醒的定义

**一次「被吵醒」= 睡眠时段内出现一次人侧事件，且距离上一次已计数的人侧事件超过 `wakeGapMinutes`（缺省 10 分钟）。**

- 判定与 P0 的「有人回来了」**完全同一套**：`origin === 'external'` 且类型不以 `.self` 结尾、且不在 `activityIgnore` 里。
- 同一次打扰里连发 5 条消息只算 1 次（间隔超过 `wakeGapMinutes` 才算新的一次）——否则微信里聊十分钟会记十几次。
- 计数进 `wokeCount`（这一夜），带 `lastWokeAt` / `lastWokeBy`（渠道类型，例如 `clawbridge.message`）。
- 睡眠时段结束时把这一夜的结果写进 `lastNight`（`wokeCount`、`firstWokeAt`、`lastWokeAt`），然后归零。

### 2.3 软件唤醒能不能排除

**能，而且规则已经现成**：

| 唤醒来源 | 事件特征 | 计不计 |
|---|---|---|
| 用户在气泡/控制台说话、戳摸、换装 | `desktop-pet.*` / `console.*`，`external` | ✅ 计 |
| 用户在微信/QQ/B 站等渠道说话 | `*.message` 等，`external` | ✅ 计 |
| 定时器、上下文交接、通知 | `coopanion.alarm` / `opening` / `notice`，`internal` | ❌ 不计（内部事件天然被排除） |
| Coo 自己做的事（说话、动作） | `desktop-pet.self` / `console.self`，`external` 但以 `.self` 结尾 | ❌ 不计 |
| 某插件把系统事件标成了 `external`（灰区） | `external` 的未知类型 | ⚠️ 会计；用 `activityIgnore` 排除，并在 debug 日志里打印被排除的类型，便于发现 |

**已知边界**：Core 没有「这个 external 事件是人还是软件」的通用标记，靠 `origin` + 类型约定。灰区只能靠 `activityIgnore` 兜。
好处是：这套判定和「安静计时」共用，不会出现「算作有人回来了但不计入被吵醒」的矛盾。

## 3. 状态共享：通道 vs 直接提示

### 3.1 两条路的差别

| 方案 | 优点 | 缺点 |
|---|---|---|
| **A. 只提供通道**（状态文件/事件） | 零额外开销；谁读谁注记，时机最准 | 需要各个插件自己接：微信桥要把「被吵醒」拼进它推的消息里；桌宠气泡/控制台没人能替我们注记 |
| **B. 插件自己给 Coo 发一条「你被吵醒了」** | 覆盖所有渠道，不用改别的插件 | 时机难保证：插件 5 秒才检查一次，消息可能已经开聊了；`flush` 会**多一次模型调用**，`piggyback` 可能迟到甚至永远不投递 |
| **C. A + 尽力而为的 B** | 微信桥这类能精确注记；桌宠/控制台由插件补一条，迟到就作废 | 两边同时生效时，Coo 可能看到两句相近的提示（可接受，也可以关掉 B） |

### 3.2 本鱼的推荐：C，但 B 用「过期作废」的 piggyback

1. **通道是主**：状态文件 + 归档事件（见 §4），微信桥以后读它，把自己那条消息注记成「（你把睡着的 Coo 吵醒了）」。
2. **B 只做兜底**：检测到人侧事件时投一条 `rhythm.woken`（`origin: internal`，`trigger: 'piggyback'`，**不触发新一轮**），
   `render()` 里判断「距离这次吵醒超过 90 秒就返回 null」——这样它只会搭上正在进行的这一轮，
   不会在对话结束半小时后突然冒出一句「你刚才被吵醒了」。
3. **开关**：`wakeHint`（缺省 true）。如果觉得和微信桥重复，或嫌吵，关掉即可；通道不受影响。

> 为什么不用 `flush`：那会在用户说完话时**额外**拉起一轮模型调用（一夜被吵几次就多几次），
> 而且可能在用户的消息之后才插进来，读起来像它自己突然生气。`piggyback` 只搭车，不发动车。

## 4. 公开状态文件（主通道）

`<dataDir>/rhythm/status.json`，状态变化时原子重写（内部 `state.json` 不受影响）：

```json
{
  "version": 1,
  "generatedAt": "2026-11-02T23:41:00+08:00",
  "sleep": {
    "active": true,
    "window": "22:00-08:00",
    "endsAt": "08:00",
    "wokeCount": 2,
    "lastWokeAt": "2026-11-02T23:38:12+08:00",
    "lastWokeBy": "clawbridge.message"
  },
  "today": { "nudges": 3, "cap": 12 }
}
```

- 只写非敏感事实：不含消息正文、token、完整用户 id、本机路径。
- 结构版本化，字段只增不减；其他软件（同进程 World 或外部脚本）直接读文件。
- 归档事件 `rhythm.woke`（`deliver:false`，不进模型上下文）作为补充，供同进程方按时间轴查。

## 5. 配置（3 个）

| 键 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `sleepHint` | boolean | true | 22:00「该睡了」/ 08:00「该醒了」两条提示 |
| `wakeHint` | boolean | true | 被吵醒时兜底提示 Coo「带点起床气」，90 秒内没搭上车就作废 |
| `wakeGapMinutes` | integer | 30 | 同一段打扰的合并间隔：超过它再有人来才算新的一次 |
| `wakeHintSeconds` | integer | 90 | 「被吵醒」提示的保鲜期（10–300 秒）：超过就作废，不事后补发 |

---

## 6. 日志

- `作息:进入睡眠时段`（已有）加 `hint: sent|skipped`
- `作息:睡眠提示`（kind: sleep|wake，phase）
- `作息:被吵醒`（`by`、`wokeCount`、`sinceLastWokeMin`）
- `作息:睡眠时段结束`（`wokeCount`、`hints`）
- debug：`作息:忽略的人侧事件`（`activityIgnore` 命中的类型，方便发现灰区）

## 7. 测试（仍用假宿主 + 假时钟）

- 22:00 进睡眠 → 恰好一条「该睡了」；`sleepHint=false` → 没有。
- 08:00 出睡眠 → 恰好一条「该醒了」。
- 掉电重进睡眠时段：不重复发（`nightKey` 已发过）。
- 睡眠内人说话 → `wokeCount=1`；10 分钟内再发 3 条 → 仍是 1；11 分钟后再来 → 2。
- `activityIgnore` 命中的 external 类型不计；`internal` / `*.self` 不计（软件唤醒）。
- `dailyCap=1` 且白天用满：夜里「该睡了」照发，但不发普通叫醒。
- `wakeHint`：piggyback 在 90 秒内 render 有正文；超过 90 秒 render 返回 null。
- `status.json` 随状态更新；睡眠外不出现睡眠提示。
- 跨午夜 `nightKey` 不变。

---

## 8. 风险

- 08:00 的「该醒了」会拉起一轮模型调用（每夜两次提示，约 2 次调用）；不想要的关 `sleepHint`。
- 睡着时用户发消息，身体可能仍是睡姿、气泡已在说话 → 提示文案里建议先用 `pet_act(["stand"])`。
- 灰区 external 事件会误计 → `activityIgnore` + debug 日志。
- 不碰桌宠其他行为（不调 `pet_quiet`、不改设置、不隐藏窗口）。

## 9. 已定（实现按此）

1. 合并间隔 **30 分钟**（`wakeGapMinutes`）。
2. **兜底提示默认开**（`wakeHint`），设置里可关；用 `piggyback` + 90 秒保鲜期。
3. 「该睡了 / 该醒了」默认开（`sleepHint`），**只在启用睡眠时段时**发送。
4. 提示文案放在 `<dataDir>/rhythm/messages.json`，首次运行生成、永不覆盖，不进设置界面。

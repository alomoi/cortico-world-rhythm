# P3 设计 · 内容感知（让叫醒接得上话）+ 影子模式

> 状态：**草案，待主人确认口味问题**。
> 前置：P0–P2 已完成；按 `testing-plan.md`，P3 动到「怎么跟 Coo 说话」→ **必须先过真机闸门**。
> 本阶段的顺序刻意设计成：**先影子（零打扰）→ 再内容 → 最后才上真机一日测**。

---

## 1. 目标

现在的叫醒正文是一句模板：「安静了大约 N 分钟……」。P3 让它**接得上刚才的事**：

- 知道最后说话的是谁、大概说了什么；
- 知道自己上次说过什么、对方有没有接话；
- 不再每次同一句（换着说法，别像复读机）；
- 仍然**不替 Coo 决定**说什么——只是给它一点上下文。

## 2. 非目标（明确不做）

| 不做 | 原因 |
|---|---|
| 调模型做「对话摘要」再塞进正文 | 每次叫醒已经是一次模型调用，再来一次就翻倍；而且慢 |
| 读 `meta.raw` / 完整消息体 | 可能有敏感信息；只读已经渲染进上下文的 `text` |
| 记住跨天的话题（长期记忆） | 那是 Persona / Memory 的事，不归我们 |
| 改 Coo 的语气或人设 | 只提供事实，不写指令 |
| 自动选择渠道（气泡/微信） | 由 Coo 自己决定 |

---

## 3. 数据从哪来

| 来源 | 用途 | 备注 |
|---|---|---|
| 事件库 `store.range({limit: 500, origin: 'external'})` | 最近的人侧消息（谁、几点、说了什么） | 与 P0 的判定同一套，`*.self` 排除 |
| 事件库里的 `*.self`（`desktop-pet.self` / `console.self`） | Coo 上次说了什么（`meta.kind` 是 say/ask 时取 `text` 或 `meta.beats[].text`） | 只有桌宠/控制台会记；微信桥不记 |
| `outputTap` 的 `function_call` 参数 | 兜底捕获「它刚说了什么」：`pet_say` 的 `script`、`console_send`/`clawbridge_send` 的 `text` | 覆盖微信等不落 self 事件的渠道；只存内存 |
| 自己的状态 | 本轮第几次、今天第几次、上次叫醒多久前 | 只进日志，不进正文（见 §6） |

**总原则**：只读「已经进过上下文」的文本片段，不解析原始报文，不落盘正文。

## 4. 正文长什么样

### 4.1 结构

```
[时刻] [作息] 安静了约 N 分钟，没人跟你说话。
对方最后一句（HH:MM）：「……」
你上次说（HH:MM）：「……」，还没人接话。      ← 没有就不出这一行
<收尾：想接着说就开口 / 想做事就用工具 / 不想就结束这一轮>
```

- 每段引用**截断到 40 字**，末尾加省略号；一行最多两段引用（`contextLines` 可调 1–4）。
- 对方没说过话 → 整段省略；Coo 没说过话 → 省略；不确定「有没有被接话」→ 不写「还没人接话」。
- 引用只保留文本，不带 `meta`、不带发送者 id。

### 4.2 示例（中文）

```
[23:41] [作息] 安静了约 35 分钟，没人跟你说话。
对方最后一句（23:06）：「今天累死了，先不聊了」
你上次说（23:10）：「那你早点睡」，还没人接话。
想接着说就在气泡里开口，想做事就用工具，不想就结束这一轮。
```

### 4.3 换说法（防复读）

收尾句按次数轮换（不需要配置，内置 3 档）：

| 次数 | 收尾 |
|---|---|
| 第 1 次 | 「想接着说就在气泡里开口，想做事就用工具，不想就结束这一轮。」 |
| 第 2 次 | 「还是没人来。想说话就说一句，不想就继续安静。」 |
| 第 3 次+ | 「一直没人来。想做点自己的事也行，想结束就结束这一轮。」 |

引用内容是每轮现取的，所以两轮之间通常不会完全一样。

## 5. 影子模式（P3.0，先做，零打扰）

新配置 `dryRun`（缺省 **false**）：

- 照常计算「什么时候该叫、该发什么提示」，但**不投递任何事件**；
- 日志写一条 `作息:[影子] 会叫醒`，带**完整正文**、距下次多少分钟、本轮第几次；
- `status.json` 增加 `plan: { nextNudgeAt, inWindow, shadow: true }`，方便你一眼看到排程；
- 不增加 `nudgesToday`，不占用「今日上限」。

**用途**：跑一整天，日志与你真实作息对得上 → 排程没问题；再关掉影子，做一次真实一日测。
小肥鱼全程不用开口。

---

## 6. 数量与隐私约束

- 正文上限约 **320 字符**（中文字符计），超了就少放一行引用。
- 引用只取 `text` 的前 40 字；**不读** `meta.raw`、`senderKey`、`blob`。
- 不写进任何状态文件：`status.json` 里只有计数与时间，没有正文。
- 日志里也不打正文（影子模式除外——那是给你排查用的，可关）。

---

## 7. 新增配置（3 个）

| 键 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `dryRun` | boolean | false | 影子模式：只算、只记日志，不投递 |
| `contextAware` | boolean | true | 叫醒正文里带最近对话的引用 |
| `contextLines` | integer | 2 | 最多引用几段（1–4；对方一段 + 自己一段） |

## 9. 测试计划（全模拟）

- **引用**：事件库有 `desktop-pet.message` 文本 → 正文包含「对方最后一句」与截断后的内容；没有 → 不出现该行。
- **自己的话**：有 `desktop-pet.self`（meta.kind=say）→ 出现「你上次说」；之后有人回 → 不写「还没人接话」。
- **微信兜底**：没有 self 事件，但 `outputTap` 抓到 `clawbridge_send` 的 text → 也能写出「你上次说」。
- **防复读**：连续三次叫醒，收尾句不同；引用内容随事件变化。
- **截断**：40 字以上被截断且加省略号；总长不超过上限。
- **隐私**：构造带 `meta.raw` 的事件，正文里不得出现其中内容。
- **dryRun**：完全不 `pushDeferred`、`nudgesToday` 不变、日志与 `status.plan` 有内容。
- **关闭 contextAware**：正文回到 P2 的样子（只多一个「安静 N 分钟」）。
- **真机闸门**：本地全绿后不再加功能，直接进 `testing-plan.md` 的影子日 → 真实一日测。

## 10. 风险

- **引用不等于理解**：短引用可能让 Coo 抓错重点；文案里已写明「只是参考」，最终仍由它决定。
- **跨渠道混淆**：微信桥的消息文本带自己的标记，引用时可能带「微信」字样；测试时观察它会不会分不清气泡和微信（主人提过这个后遗症）。
- **token 增加**：每次叫醒正文变长几十字，属于可接受范围；不开 `contextAware` 即可回到原样。
- **影子模式被误开**：`status.json` 的 `plan.shadow` 与状态灯会标出来，避免「以为坏了」。

# 睡前宽限期（上床 → 入睡两段式）· 设计（v1，已实现，待真机验证）

> 版本目标 1.1.0。起因：小肥鱼睡前有道晚安的习惯，而睡眠时段一进就算「被吵醒」，
> 回一句晚安体验很差；同时做梦的安静检查也从窗口一开始就算，睡前聊天会把梦往后推。

## 1. 问题

| 现状 | 问题 |
| --- | --- |
| 22:00 进窗口 → 立刻算睡眠 | 主人回一句晚安就成了「今夜第 1 次被吵醒」，桌宠要带起床气 |
| 做梦计划在入夜时掷 | 睡前那段聊天也算「不安静」，梦被顺延或跳过 |
| 只有一条「该睡了」 | 没有「先道晚安、收个尾」的余地，提示语直接要求躺下 |

## 2. 方案：把入睡拆成两步

```
22:00  入睡预告（kind = bedtime）
       「你的眼皮越来越重，该准备睡觉了。想说话就用你平时的方式道个晚安，
         想做事就用工具，不想就结束这一轮。」
       ↓ 宽限期（bedtimeGraceMinutes，缺省 20 分钟）
       这期间：正常聊天；不算吵醒；不做梦；不叫醒；不投递「该醒了」
22:20  真正入睡（kind = sleep）
       「一阵强烈的睡意袭来，你睡着了。用一个能让你躺下的动作（比如睡眠）躺好，
         做完就结束这一轮。」
       ↓ 从这一刻起，才有「被吵醒」计数与做梦计划
08:00  该醒了（kind = wake，不变）
```

### 2.1 为什么是 20 分钟

人类从躺下到入睡通常 15–30 分钟。取 20 分钟：够说完晚安、收个尾，又不至于把整夜往后拖。
可在设置页调（5–60）。

### 2.2 宽限期内的互动

- **不算「被吵醒」**：这一段的打扰不是打扰。
- **不重置倒计时**：否则一直聊就永远不睡。到点照样睡。
- **顺带把退避清零**：既然有人说话了，`unanswered` 本来就该归零（沿用既有语义）。
- 说「晚安」这件事本身不改任何状态——插件不判断「是不是晚安」，只给时机。

### 2.3 做梦

- 骰子在**正式入睡**那一刻才掷（不在入夜时掷）。
- 安静检查从正式入睡起算，所以睡前聊天不再挤掉整夜的梦。
- 顺延逻辑不变：到点前安静不够就顺延到「最后一次打扰 + dreamAfterMinutes」，窗口放不下才跳过。

### 2.4 重启

| 情况 | 行为 |
| --- | --- |
| 宽限期内重启 | 接着等，到点照常发「睡意袭来」 |
| 已入睡后重启 | 不补发任何提示（沿用现有 `nightKey` 逻辑） |
| 已经到点但停机 | 恢复后补发一次「睡意袭来」，只补一次（`sleepHintSent` 由它标记） |

## 3. 配置

| 键 | 类型 | 缺省 | 说明 |
| --- | --- | --- | --- |
| `bedtimeGraceMinutes` | integer | **20** | 入睡预告与真正入睡之间的间隔；5–60 |

`sleepHint` 仍是总开关：关掉就既没有预告也没有入睡提示（回到「夜里静默」）。
文案在 `data/rhythm/messages.json` 里改：`bedtime` 改预告、`sleep` 改入睡；老文件自动补 `bedtime`，不覆盖已改内容。

## 4. 文案（默认）

```json
"bedtime": "[{at}] [作息] 你的眼皮越来越重，该准备睡觉了。\n想说话就用你平时的方式道个晚安；想做事就用工具，不想就结束这一轮。",
"sleep":   "[{at}] [作息] 一阵强烈的睡意袭来，你睡着了。\n用一个能让你躺下的动作（比如睡眠）躺好，做完就结束这一轮。"
```

## 5. 状态与可观测性

- `state.json` 的 `sleep` 里加 `asleepAt`（真正入睡的时刻，ISO）。
- `status.json` 增加 `sleep.phase`（不在窗口内为 `null`）/ `bedtime` / `asleep`。
- 日志：
  - `作息:进入睡眠时段（宽限期）{grace}` → 预告已发
  - `作息:正式入睡 {grace}` → 入睡提示已发；此刻掷梦
  - 宽限期内的打扰：`作息:宽限期内有人说话，不算吵醒 {by}`

## 6. 测试（假宿主 + 假时钟）

- 22:00 发 `bedtime`；22:20 发 `sleep`；08:00 发 `wake`——三条各一次；
- 宽限期内来消息 → `wokeCount` 仍为 0、无 `woken` 提示；
- 宽限期内的消息不会推迟 22:20 的入睡；
- `bedtimeGraceMinutes=0` → 两条提示连着发（退化为旧行为）；
- 做梦骰子在 22:20 才掷；宽限期内的聊天不影响计划的安静起点；
- 窗口太短（短于宽限期 + 10 分钟）时不分两段：直接发 `sleep`，退化为旧行为。

## 7. 风险

- 多一条提示 = 每夜多一次模型调用（约 2 → 3 次）。不想要的可以关 `sleepHint`。
- 宽限期太短（< 5 分钟）时体验退化成旧版；太长（> 60）会拖到深夜。

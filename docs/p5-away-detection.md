# P5 候选功能 · 主人是否在电脑前（锁屏 / 屏保 / 空闲）

> 状态：**可行性分析，暂不实现**（按主人要求记录，排在本次实机测试之后）。
> 想法：叫醒前先判断电脑是否锁屏/屏保/长时间无输入，把结果和叫醒一起给 Coo，
> 让它知道「主人可能不在」，从而选择不打扰、或用别的渠道。

---

## 1. 结论先说

**可行，但要走本机探测，不能直接用 Electron 的 `powerMonitor`。**

原因：Coopanion 的 Core 是主进程 `fork()` 出来的子进程（`resources/app/app/core-host.cjs`），
以 Node 模式运行（`ELECTRON_RUN_AS_NODE`）。在子进程里 `require('electron')` 只拿到可执行文件路径，
拿不到 `powerMonitor` / `powerMonitor.getSystemIdleState()`。主进程也没有向外暴露这类查询。

---

## 2. 探测方式（Windows）

在 Core 子进程里用 `node:child_process` 调 PowerShell，读 Win32 状态：

| 信号 | 实现 | 可靠性 |
|---|---|---|
| **空闲时长** | `GetLastInputInfo`（user32，P/Invoke） | 高，无需管理员；但「看视频不动鼠标」也会很长 |
| **锁屏** | `OpenInputDesktop` 失败 / 当前桌面是 Winlogon；或 `LogonUI.exe` 在跑 | 中高；RDP/多桌面场景要单独确认 |
| **屏保** | `SystemParametersInfo(SPI_GETSCREENSAVERRUNNING)` 或 `scrnsave.scr` 进程 | 中；Windows 10+ 的「锁屏后屏保」行为有差异 |
| **macOS / Linux** | 各自有 `pmset` / `loginctl`，差异大 | 先返回 `unknown`，按「正常」处理 |

工程约束：

- **只在叫醒到点那一次探测**，加 60 秒缓存；不要每 5 秒 spawn 一个 PowerShell。
- 子进程 spawn 有 150–400ms 启动开销，加超时（1.5–2 秒），超时按 `unknown` 处理。
- 探测失败一律 `unknown`，**不改变**原有行为——宁可不聪明，也不要误判。

---

## 3. 行为设计（比探测更重要）

**先说一个现实**：如果锁屏时想「换个渠道」，可选的基本只有微信——而微信桥是 reply-only，
24 小时内对方没先说话就发不出去。所以「改用别的渠道搭话」大多数时候**不可行**。

因此建议分两种处理：

| 状态 | 建议行为 | 理由 |
|---|---|---|
| **锁屏 / 屏保** | **跳过这次叫醒**，等解锁后的下一拍再说（`pauseWhenLocked`，缺省开） | 屏幕前没人，叫醒=白烧 token，还可能让形象在没人看时说话 |
| **空闲很久但没锁屏** | **照常叫醒，正文里带一句事实**（「屏幕已经 40 分钟没有输入，主人可能在忙/不在」），由 Coo 自己决定 | 看视频、开会共享屏幕都会「空闲但人在」，直接跳过会误伤 |
| **探测失败 / 平台不支持** | 按正常处理 | 保守优先 |

可选补充：解锁时投一条「主人回来了」的轻提示？**不建议**——会增加模型调用，而且人刚回来时不需要被打扰。

---

## 4. 正文长什么样（若启用「带事实」）

```
[15:02] [作息] 安静了约 35 分钟，没人跟你说话。
屏幕已经 40 分钟没有输入，主人可能不在电脑前。
想说话就用你平时的方式说一句，想做事就用工具，不想就结束这一轮。
```

不写「用别的渠道」这种指令——渠道现实摆在那，交给 Coo 自己判断更诚实。

## 5. 新增配置（预计 4 个）

| 键 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `awayDetection` | boolean | false（先关） | 是否启用本机探测（Windows 有效，其他平台自动 unknown） |
| `pauseWhenLocked` | boolean | true | 锁屏/屏保时跳过本次叫醒 |
| `awayIdleMinutes` | integer | 10 | 超过这么久无输入，在正文里提示「可能不在」 |
| `awayHint` | boolean | true | 是否把探测结果写进叫醒正文 |

---

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 空闲误判（看视频） | 只有「锁屏/屏保」才跳过；空闲只提示 |
| 锁屏误判 | 探测失败 → unknown；只认明确信号；先跑只读探测脚本观察几天 |
| spawn 开销/卡死 | 只在到点探测 + 60 秒缓存 + 2 秒超时 |
| 跨平台差异 | 非 Windows 返回 unknown，行为不变 |
| 隐私 | 只读「是否锁屏/空闲多久」，不读窗口标题、不截屏 |

## 7. 验证方式

1. **先跑只读探测脚本**（不改插件）：在本次实机测试期间，手动执行一次，确认锁屏/解锁时输出正确。
2. 插件实现后用注入式测试：把探测结果作为参数注入 `world`，模拟 `locked` / `idle` / `unknown` 三态，
   断言「跳过叫醒」「正文带事实」「unknown 不改变行为」。
3. 真机验证：锁屏放一会儿，确认日志出现 `作息:锁屏，跳过叫醒`；解锁后正常。

## 1. 现状：这套流程已经在跑了，只是由 Coo 自己承担

Coo 的做法（见 `self-initiated-chat.md`）：

1. 被上游插件叫醒 → 它自己跑 `partner/idle.ps1`；
2. 脚本调 `probe.cs`（`OpenInputDesktop` + `GetLastInputInfo`），输出 `desktop=` / `idle_seconds=` / `locked=`；
3. `locked=false` → 气泡；`locked=true`（或空闲很久）→ 微信；
4. 它还给自己写了规则，**专门用来无视上游那句「在气泡里跟对方说点什么」**。

代价（主人担心的负担）：

- 每次叫醒都要多一次 `sh` 工具调用 + PowerShell 启动（300ms 级）+ 读输出；
- 要一直记着「别跟着提示文走」，这属于**持续的心智负担**；
- 上游的提示文不允许它知道主人在不在，所以它每次都只能自己查。

**插件的价值**：把探测做成一次性的、确定的、写在叫醒正文里的事实，Coo 就不用再自己跑脚本、也不用再对抗文案。

---

## 2. 探测方式（默认不编译任何代码）

**默认只查锁屏**，用一条纯 cmdlet：

```
powershell.exe -NoProfile -NonInteractive -Command "Get-Process -Name LogonUI, LockApp ..."
```

- Win10/11 锁屏时，`LogonUI`（安全桌面）或 `LockApp` 至少有一个在跑；
- 只读进程名：不写文件、不联网、不改注册表、不用 `-EncodedCommand`、不用 `-ExecutionPolicy Bypass`；
- 兼容 Windows 自带的 **PowerShell 5.1**（脚本只用最基础的语法，不需要 PowerShell 7）。

**可选：多测一个「键鼠空闲多久」**（`awayIdleProbe`，默认关）。

- 需要 `Add-Type` 内联编译 C# 调 `GetLastInputInfo`，与 Coo 的 `probe.cs` 等价；
- 代价：运行时会编译代码（杀软/EDR 的常见告警点），首次约 1 秒；
- 代码按 C# 5 / PS 5.1 写；只有在用户显式打开时才走这条路径。

| 项 | 做法 | 备注 |
|---|---|---|
| 调用时机 | 只在叫醒到点那一次（影子模式也算一次） | 不在 5 秒 tick 里跑 |
| 缓存 | 60 秒 | 同一分钟内不重复 spawn |
| 超时/失败 | 2 秒超时；失败返回 `unknown`，正文不加任何假设 | 保守优先 |
| 平台 | 仅 Windows；其他平台直接 `unknown` | 不改变原有行为 |

输出约定：`{ state: 'active' | 'idle' | 'locked' | 'unknown', idleSeconds: number | null }`

## 3. 行为设计（按主人的真实流程修正）

早期草案写的是「锁屏就跳过叫醒」——**这是错的**。主人的实际用法是：**锁屏时更希望它走微信**。
所以默认改成：

| 状态 | 默认行为 | 理由 |
|---|---|---|
| **锁屏** | **照常叫醒，正文写「主人现在不在电脑前（屏幕锁着）」**，由 Coo 自己决定渠道 | 微信能触达手机；主人明确在等这种联系 |
| **空闲很久但没锁屏** | 照样叫醒，正文写「屏幕已经 N 分钟没有输入」 | 看视频/开会也会空闲，不能当锁屏处理 |
| **unknown** | 正文不提，行为不变 | 探测失败不要制造假事实 |

可选开关 `pauseWhenLocked`（缺省 **false**）：给「不装微信、也不希望它对着空房间说话」的人用；
打开后锁屏期间跳过叫醒，解锁后下一拍再说。

## 4. 正文长什么样

```
[15:02] [作息] 安静了约 35 分钟，没人跟你说话。
主人现在不在电脑前（屏幕锁着）。        ← 或：屏幕已经 40 分钟没有输入，可能在忙。
想说话就用你平时的方式说一句，想做事就用工具，不想就结束这一轮。
```

- **不写渠道建议**（不写「用微信」「别用气泡」）——渠道由 Coo 自己判断；
  我们只给事实，保持和 P3 一致的「不替它决定」原则。
- 事实行只在探测成功时出现；`unknown` 时正文与现在一模一样。

---

## 5. 收益与成本

**收益**

- 每次叫醒省掉一次 `sh` 工具调用 + 一次 PowerShell 启动；
- 省掉「对抗旧文案」的心智负担（P3 已把「在气泡里」改成渠道中性，P5 再补上「人在不在」）；
- 探测结果同时写日志与 `status.json`，出问题时能对照。

**成本**

- 每次叫醒多一次 PowerShell 启动（约 200–400ms），只在到点发生；
- 需要一次真机验证（锁屏/解锁各测一次），正好可以并进本次测试；
- 跨平台没有实现，非 Windows 无效果。

## 6. 新增配置（预计 4 个）

| 键 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `awayDetection` | boolean | **true**（仅 Windows 生效；默认只查锁屏，不编译） | 叫醒时探测锁屏/空闲，并把事实写进正文 |
| `awayIdleMinutes` | integer | 10 | 超过这么多分钟无输入，正文提示「可能不在」 |
| `pauseWhenLocked` | boolean | **false** | 打开后锁屏期间跳过叫醒（解锁后补） |
| `awayHint` | boolean | true | 是否把探测结果写进正文（关掉只写日志） |
| `awayIdleProbe` | boolean | **false** | 额外取键鼠空闲秒数（Add-Type，会编译） |

## 7. 测试计划

1. **真机对照（本次测试期间顺手做，零风险）**：手动跑一次 `idle.ps1`，同时让插件（临时打开
   `awayDetection`）在日志里打一条探测结果，比对两者是否一致。
2. 模拟测试：把探测结果作为参数注入 `world`，覆盖 `locked` / `idle` / `unknown`：
   - `locked` → 正文出现「不在电脑前」且**仍然投递**（默认不跳过）；
   - `pauseWhenLocked=true` → 锁屏时不投递、日志写明跳过；
   - `idle` 超过阈值 → 正文出现空闲分钟数；
   - `unknown` → 正文与现在完全一致；
   - `awayHint=false` → 只写日志，正文不变。
3. 崩溃兜底：探测超时/脚本报错 → `unknown`，不影响叫醒。
